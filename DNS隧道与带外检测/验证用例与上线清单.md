# 验证用例与上线清单

---

## 一、上线前校验

### 1.1 语法/加载校验

```bash
# 先确认版本必须为 8.0.8
suricata --version

suricata -T -c /etc/suricata/suricata.yaml \
          -S /etc/suricata/rules/DNS隧道与带外检测规则.rules -v
```

- 看到 `Configuration provided was successfully loaded` 即为通过。
- 若报 `unknown variable "CLIENT_NET"`：在 `suricata.yaml` 的 `vars.address-groups` 中定义。
- 若报 `dataset ... could not be processed`：检查 `.lst` 是否有逗号或空行异常。
- 若报 `couldn't load file` / `couldn't prime file`：`.lua` 不在 `default-rule-path`，或 Lua 语法错误；先确认 `lua/*.lua` 已复制到 `/etc/suricata/rules/`。
- 若报 `Lua rules disabled`：打开 `security.lua.allow-rules`。
- 若报 `unknown rule keyword lua`：当前构建未启用 Lua（`--disable-lua`），需要换启用 Lua 的 8.0.8 构建。

### 1.2 生产加载方式

不要长期用 `-S`（它只加载指定文件）。把规则加入 `suricata.yaml` 的 `rule-files`，并**移除旧文件**：

```yaml
rule-files:
  - DNS隧道与带外检测规则.rules
```

> 新旧文件 SID 相同，同时加载会冲突。

### 1.3 EVE DNS 日志

规则调参、影子期统计与复盘依赖 EVE 的 DNS 事件，确认 `eve-log` 中启用了 DNS：

```yaml
outputs:
  - eve-log:
      enabled: yes
      types:
        - dns:
            query: yes
            answer: yes
```

### 2.3 建议的抓包/回放方式

```bash
# 生成测试查询（示例）
dig @10.0.0.53 a.b.c.d.e.f.g.example.com A
dig @10.0.0.53 0123456789abcdef0123456789abcdef.tunnel.example.com TXT
dig @10.0.0.53 abc.oast.pro A

tcpreplay -i eth1 dns-test.pcap
```

> 注意：`dig -x` 的 PTR 查询应确认未被解析器本地缓存/拦截。

## 三、影子期统计（上线第 1–2 周）

### 3.1 按规则统计命中量

```bash
jq -r 'select(.event_type=="alert") | .alert.signature_id' eve.json \
  | sort | uniq -c | sort -rn
```

### 3.2 每条规则 Top 来源

```bash
jq -r 'select(.event_type=="alert" and .alert.signature_id==9109002)
       | .src_ip' eve.json | sort | uniq -c | sort -rn | head -20
```

### 3.3 每条规则 Top 域名

```bash
jq -r 'select(.event_type=="alert" and .alert.signature_id==9109002)
       | .dns.queries[0].rrname' eve.json | sort | uniq -c | sort -rn | head -50
```

### 3.4 TXT 响应体积（调参参考）

```bash
# 兼容 DNS v2（type=query/answer）与 v3（type=request/response）：不按 type 过滤
jq -r 'select(.event_type=="dns")
       | .dns.answers[]? | select(.rrtype=="TXT")
       | [.rrname, (.rdata|length)] | @tsv' eve.json \
  | sort -k2 -nr | head -20
```

### 3.5 白名单命中率（评估是否过宽/过窄）

把影子期所有查询的注册域与 `dns_tunnel_allow.lst` 做匹配，统计：

- 白名单域名占全部查询的比例；
- 白名单里**零命中**的条目（候选删除）；
- 高频命中但不在白名单的域名（候选新增）。

## 四、上线检查清单

- [ ] `$CLIENT_NET` 已定义，且**不包含** DNS 服务器、邮件网关、扫描器、沙箱
- [ ] `dns_tunnel_allow.lst` 与规则同目录，条目带前导点，无注释/逗号
- [ ] 已确认版本为 **Suricata 8.0.8**（`suricata --version`）
- [ ] `to_lowercase` / `dns.rrtype` / `match subdomain` 已通过 `suricata -T` 加载验证
- [ ] `lua/*.lua`（8 个脚本）已复制到 default-rule-path
- [ ] `security.lua.allow-rules` 为开启状态；`stats.log` 中 `lua_rule_errors` 为 0
- [ ] 已用测试流量确认 9109203 的 `flowbits:dns_susp` 在 query/response 间生效
- [ ] 旧规则文件已移除，避免 SID 冲突
- [ ] EVE DNS query/answer 日志已开启
- [ ] SIEM 已按 `tier alert` / `tier triage` / `tier telemetry` 分流
- [ ] 安全设备与授权红队的 `suppress` 已配置，且有到期日
- [ ] 影子期 ≥ 2 周，Top 域名已评审并形成白名单
- [ ] 回滚方案已演练

## 五、回滚方案

1. 保留旧规则文件的备份（不要删除）。
2. 回滚时把 `rule-files` 指回旧文件，移除新文件。
3. `suricata -T` 通过后 `systemctl reload suricata`。
4. 白名单与抑制配置可保留（它们不影响旧规则）。
5. 回滚原因与时间写入变更记录，避免重复踩坑。

## 六、验收指标（建议写入项目验收）

| 指标 | 目标 | 采集方式 |
|---|---|---|
| 告警 precision | ≥ 95% | 每周抽样 50 条人工判定 |
| 误报工单 | ≤ 5 件/天 | 工单系统 |
| 正例召回 | ≥ 90% | 第二节正例集每季度回归 |
| 反例误报 | 0 | 第二节反例集每季度回归 |
| 隧道 MTTD | ≤ 15 min | 首查询 → 事件 |
| 白名单过期条目 | 0 | 周复核 |
| 抑制无工单/无到期 | 0 | 月度审计 |
| 编码隧道召回（base32/拆分） | ≥ 80% | 规则内 Lua 9109201 合成集 |
| 响应侧 TXT 召回 | ≥ 80% | 规则内 Lua 9109202/9109203 合成集 |
| 请求+响应确认精度 | ≥ 95% | 9109203 抽样 |
| OOB token 过滤 | ≥ 90% | 9109004/5 合成集 |

> 慢速/低频隧道、跨事务唯一子域统计不在规则层能力范围，本包不提供规则外脚本，也不列入验收。

- 若 9109201 不命中用例 2，调低 `dns_tunnel_request.lua` 的 `SCORE_THRESHOLD` 或 `ENCODED_LABEL_MIN`。
- 若 9109202/9109203 误报用例 8/9，检查 `VERIFICATION_PREFIXES` 与 payload 分类逻辑。

> 跨事务聚合、慢速/长窗口分析不属于本包；本包只交付规则、Lua 脚本与 dataset。
