# 精准化改造方案（L0–L5）

> 目标：把"7 条正则直接告警"改造成"高置信 IOC 直接告警 + 结构化规则 + 规则内 Lua 评分产生线索"的规则内检测。
> 本包只交付规则层（L1/L2）与规则内 Lua；L0/L3/L4/L5 仅作边界说明，**不包含实现、脚本或工具**。

---

## 一、设计原则

1. **检测层不抑制，输出层才限流。** 规则命中即产生事件；去重、限流、抑制放在 `event_filter` 或部署方的处置流程，避免"阈值把第二条隧道吃掉"。
2. **每个规则只回答一个明确问题。** 不要用一条规则同时做"隧道 + OOB + DGA + 频次"。
3. **单包特征只做线索，跨包统计才做结论。** 单包能看到的只有"名字长、像随机"；隧道的本质是"持续、唯一、双向"。
4. **白名单是一等公民。** 没有 owner、没有到期时间的白名单就是后门。
5. **分级输出。** `tier=alert`（直接工单）与 `tier=telemetry`（观察/狩猎）必须分离。
6. **可回归。** 每条规则都要有正例、反例、灰度期指标，改规则必须跑用例。

---

## 二、分层架构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ L5 响应闭环  隔离 / 封禁 / 全量 DNS 回溯 / 取证 / 复盘               │
├──────────────────────────────────────────────────────────────────────┤
│ L4 资产与身份  资产重要性 / 用户 / EDR 进程 / 代理 & TLS SNI 关联    │
├──────────────────────────────────────────────────────────────────────┤
│ L3 统计评分  唯一子域比 / 标签熵 / qtype 混合 / NXDOMAIN / TXT 体积  │
├──────────────────────────────────────────────────────────────────────┤
│ L2 结构化规则（本包规则） qtype + 锚定 + 白名单 + 来源范围 + 分级    │
├──────────────────────────────────────────────────────────────────────┤
│ L1 高置信 IOC  OOB 平台域名 / 已知隧道域名 / 威胁情报                │
├──────────────────────────────────────────────────────────────────────┤
│ L0 可见性  客户端→解析器镜像 / 解析器日志 / DoH·DoT 治理 / 出口策略  │
└──────────────────────────────────────────────────────────────────────┘
```

### 各层职责与产出

| 层 | 数据源 | 产出 | 误报控制方式 |
|---|---|---|---|
| L0 | 交换镜像、解析器查询日志、DHCP/资产库 | 完整 `client_ip × qname × qtype × rcode × answers` | 看不到就没有误报问题，只有盲区问题 |
| L1 | 检测规则中的 OOB 域名 + 情报 IOC | 直接告警（P1/P2） | 域名精确匹配 + 结尾锚定 + 授权窗口 |
| L2 | 检测规则中的结构化规则 | 线索事件 | qtype、白名单、来源范围、`tier` |
| L3 | EVE/Zeek → SIEM/ClickHouse | 风险评分/事件 | 多特征联合，单特征不成立 |
| L4 | CMDB、EDR、代理、TLS SNI | 定级与归因 | 资产白名单、授权窗口、业务上下文 |
| L5 | SOAR/人工 | 处置与复盘 | 复盘结果反哺白名单与阈值 |

## 三、规则层改造（对应 `DNS隧道与带外检测规则.rules`，Suricata 8.0.8）

| 原规则 | 改造动作 | 目的 |
|---|---|---|
| R1 单字符标签 | `to_lowercase` → `dotprefix` → `dns.rrtype:!PTR` → 白名单 → `$CLIENT_NET` → `lua:dns_compact_labels.lua` | 消除 IPv6 PTR 与层级命名误报 |
| R2 32 位 hex | 同上 + 结尾 `$` + 至少两级域名 + `lua:dns_tunnel_request.lua` | 减少 CDN 的 A 查询误报 |
| R3 UUID | 同上 + 结尾 `$` + `lua:dns_tunnel_request.lua`（UUID 版本/变体校验） | 减少设备 GUID 误报 |
| R4 OAST | 结尾 `$` + 补 `oast.online/me` + `content:fast_pattern` + `lua:dns_oob_request.lua` | 消除"前缀相同"/根域误报 |
| R5 其他 OOB | 结尾 `$` + 精确列表 + `lua:dns_oob_request.lua` | 消除"包含平台名"/根域误报 |
| R6 长标签 | 非 PTR + 白名单 + `lua:dns_tunnel_request.lua` + `tier telemetry` | 过滤低熵/IDN/AV 长标签 |
| R7 高频 | `type both` + `count 200/60s` + 白名单 + `tier telemetry` | 消除 NAT 告警风暴 |
| 新增 | DoT 853 + `tls.alpn:"dot"` + `lua:dns_dot_policy.lua` | 过滤非 DoT/已批准解析器 |
| 新增 | DoH `application/dns-message` + `lua:dns_doh_policy.lua` | 过滤普通应用 Content-Type 误报 |
| 新增 | TXT 突发 + `lua:dns_txt_burst.lua` | 过滤邮件认证/服务发现 |
| 新增 Lua | 9109201 请求侧评分 + `flowbits:set,dns_susp` | 补 base32/base64url/拆分标签 |
| 新增 Lua | 9109202 响应侧 TXT/NULL/CNAME 评分（tier triage） | 补响应侧外泄 |
| 新增 Lua | 9109203 请求+响应联合确认（`flowbits:isset` + `lua:dns_tunnel_confirm.lua`，tier alert） | 降低 A/AAAA CDN/DGA 误报 |

> 依赖：`$CLIENT_NET`、`dns_tunnel_allow.lst`、`lua/*.lua`；版本锁定 **Suricata 8.0.8**（`dns.rrtype`、`match subdomain`、`to_lowercase`、Lua 规则）。规则内嵌脚本只支持 Lua，不支持 Python。

## 四、L3 统计特征（边界说明，不在本包实现）

### 4.1 聚合键与窗口

- 主键：`client_ip + registered_domain`（注册域用 PSL 取 eTLD+1）
- 窗口：5 分钟（滚动），长周期 30 分钟/24 小时用于慢速外泄
- 数据：Suricata EVE `dns` 事件（含 `qtype`、`rcode`、`answers`）或 Zeek `dns.log`

### 4.2 特征定义

| 特征 | 定义 | 正常基线（示例） | 隧道特征 |
|---|---|---|---|
| `q_total` | 窗口内查询数 | 依业务 | 高或稳定心跳 |
| `q_uniq` | 唯一 qname 数 | 中 | 接近 `q_total` |
| `uniq_ratio` | `q_uniq / q_total` | 0.2–0.7 | > 0.9 |
| `label_entropy` | 最左标签字符香农熵（bit/char） | 2.5–3.5 | ≥ 3.8（hex≈4.0，base64≈5.0） |
| `max_label_len` | 最长标签长度 | < 30 | 40–63 |
| `avg_label_len` | 平均标签长度 | < 15 | > 25 |
| `hex_ratio` / `b32_ratio` / `b64_ratio` | 标签字符中对应字符集占比 | 低 | 高 |
| `txt_ratio` | TXT 查询占该域查询比例 | 低（邮件域除外） | 高 |
| `null_ratio` | NULL 查询占比 | ≈0 | 高（经典隧道） |
| `cname_ratio` | CNAME 查询占比 | 低 | 中高 |
| `nxdomain_ratio` | NXDOMAIN 响应占比 | 低 | 中高（无回包隧道） |
| `txt_bytes` | TXT rdata 总字节（响应侧） | 低 | 高（外泄） |
| `answer_cnt` | 平均答案数 | 1–5 | 异常多/少 |
| `ttl_min` | 最小 TTL | 30–3600 | 极低（0–5） |
| `cname_depth` | CNAME 链最大长度 | 0–2 | > 3 |
| `subdomain_depth` | 标签层数 | 2–4 | > 5 |
| `ia_cv` | 查询间隔变异系数 | 高 | 低（固定心跳） |

> 熵的参考值：随机 hex ≈ 4.0；随机 base32 ≈ 4.0；随机 base64url ≈ 5.0–5.5；英文单词 ≈ 2.5–3.3。不要用单一阈值，按注册域基线做 z-score 或分位数。

### 4.3 评分示例（起步权重，需按环境校准）

```text
score =  2.0 * I(uniq_ratio >= 0.85 且 q_uniq >= 20)
       + 2.0 * I(label_entropy >= 3.8)
       + 1.5 * I(max_label_len >= 30)
       + 2.0 * I(txt_ratio >= 0.50 且 txt_bytes >= 1024)
       + 1.5 * I(nxdomain_ratio >= 0.30)
       + 1.0 * I(cname_depth >= 3)
       + 1.0 * I(ttl_min <= 5)
       + 1.0 * I(注册域年龄 < 30 天)
       + 1.0 * I(该注册域 7 天内首次出现)
```

| 分数 | 处置 |
|---|---|
| ≥ 6 | 升级事件（P2），自动进入工单 |
| 4–6 | 进入人工研判队列（SLA 4h） |
| 3–4 | 观察列表，结合部署方上下文再定 |
| < 3 | 仅留存，不展示 |

**重要**：权重与阈值必须用影子期数据回算。先用 30 天历史日志跑一遍，统计每个特征的分布，再定分位数；不要直接抄示例值。

### 4.4 推荐实现

- **规则内 Lua**：单事务的熵/字符集/标签结构/响应 TXT 判断由 `lua/dns_tunnel_request.lua` 与 `lua/dns_tunnel_response.lua` 完成。
- **跨事务聚合不在本包范围**：唯一子域比、NXDOMAIN 比、慢速/长窗口等特征只作为分析维度列出，规则层不实现，也不提供规则外脚本。
- 规则层只负责产生高置信 IOC 与结构化线索；事件升级由部署方的 SIEM/流程决定，不属于本包交付。

## 五、白名单治理

### 5.1 数据模型（建议用 CMDB/表格维护，再手工生成 `.lst`）

| 字段 | 说明 |
|---|---|
| `suffix` | 注册域或子域后缀，如 `microsoft.com`；生成 `.lst` 时加前导点 |
| `owner` | 业务/系统负责人 |
| `reason` | 业务用途、为何会产生哈希/GUID/长标签 |
| `ticket` | 申请单号 |
| `created_at` / `expires_at` | 最长 90 天，到期后人工移除 |
| `review_cycle` | 周/月 |
| `security_exception` | 是否属于 OOB/隧道平台（此类**永不允许**进白名单） |

### 5.2 规则

1. **禁止**把公共后缀（`com`、`co.uk`、`com.cn`）加入白名单；维护时按 PSL 校验。
2. **禁止**把已知 OOB/隧道平台加入白名单（即使业务在用，也应走授权窗口而非白名单）。
3. 优先按**注册域**放行，不要放行整个云厂商（如 `.amazonaws.com` 这种过宽后缀要单独评审）。
4. 每条白名单必须有到期时间；到期前 7 天提醒 owner。
5. 周复核：Top 100 命中域名、白名单命中率、过期条目。
6. **白名单文件必须去重、转小写、去注释、去逗号**：Suricata 的 dataset 加载器不识别 `#` 注释，含逗号的行会被当成 datarep 而加载失败。

### 5.3 Suricata 侧实现

```text
dns.query; to_lowercase; dotprefix;
dataset:isnotset,dns_tunnel_allow, type string, match subdomain, load dns_tunnel_allow.lst;
```

- `to_lowercase` 解决解析器 0x20 大小写随机化导致的匹配失效。
- `dotprefix` 解决注册域本身（`example.com`）不被后缀匹配的问题。
- `match subdomain` 让 `a.b.example.com` 命中白名单 `.example.com`。
- `isnotset` 表示"不在白名单才继续匹配"。

> 若使用 Suricata 8，可评估 `domain` 变换（内置 PSL）替代 `dotprefix + match subdomain`；但需确认现场版本与 PSL 数据。

## 六、抑制与分级

### 6.1 分级

| 级别 | 规则 | 通道 | SLA |
|---|---|---|---|
| A · 直接告警 | R4/R5、已知隧道 IOC、DoT/DoH 违规 | 工单/IM | P1–P2 |
| B · 研判队列 | R1/R2/R3 | 队列 | 4h |
| C · 观察/狩猎 | R6、R7、TXT 突发 | 仅留存/日报 | 无 |

### 6.2 抑制对象

- 漏洞扫描器、红队、渗透测试（按源 IP + 时间窗口，工单号必填）
- 邮件安全网关 / 沙箱 / URL 检测设备（按源 IP；它们会引爆 canarytokens/OOB 链接）
- DNS 分类/过滤服务
- 已知业务 SaaS（优先白名单，不要用 suppress 掩盖）

### 6.3 配置

- 规则层不再写 `threshold type limit`（它会在检测层丢事件）；告警去重/限流统一放 `event_filter` 或 SIEM。
- 全局限流放 `threshold.config` 的 `event_filter`（见 `阈值与抑制示例.conf`）。
- 所有抑制必须有 `expires_at` 与工单号；每月审计"被抑制事件量"，防止抑制变成盲区。

## 七、DoH / DoT 治理（结构性盲区）

1. **出口策略**：默认阻断 TCP/853 与已知 DoH 端点，仅放行批准的解析器。
2. **检测**：
   - TLS 853 出站（配套规则 9109101）
   - HTTP `Content-Type: application/dns-message`（配套规则 9109102）
   - 已知 DoH 域名 SNI（`dns.google`、`cloudflare-dns.com`、`dns.quad9.net`、`mozilla.cloudflare-dns.com` 等）
   - JA4/JA3 + SNI 异常组合
3. **强制内网解析**：DHCP/GPO/MDM 下发内网 DNS；浏览器 DoH 策略关闭（企业策略）。
4. **无法阻断时**：在防火墙/代理侧记录 SNI 与目标，至少保留元数据。

## 八、部署拓扑

```text
终端 ──► 内网递归解析器 ──► 上游/权威
   │            │
   │            └─ 镜像 B：resolver→upstream（看到解析器递归，源 IP 是解析器）
   └─ 镜像 A：client→resolver（看到真实客户端 IP，推荐主检测点）

解析器查询日志 ──► SIEM（补齐 client_ip、rcode、answers）
EVE/Zeek ────────► SIEM/ClickHouse（L3 聚合）
EDR ─────────────► 进程/命令行（L4 归因）
代理/TLS ────────► SNI/域名关联（L4 验证）
```

**关键点**：如果只有出口镜像，源 IP 是解析器/NAT，`by_src` 频次规则必然误报且无法归因到终端。此时必须用解析器日志做客户端归因，IDS 侧规则只做"域名级"检测，不做"终端频次"检测。

## 九、上线与调优

### 9.1 阶段

| 阶段 | 时长 | 动作 | 退出条件 |
|---|---|---|---|
| 0 基线 | 1 周 | 导出 30 天 DNS 日志，统计 Top 域名、qtype 分布、标签长度分布、NXDOMAIN 比 | 形成初版白名单与阈值 |
| 1 影子 | 2 周 | 加载规则，只记录；SIEM 路由到观察队列 | 每条规则日均命中、Top 来源/域名清晰 |
| 2 分级 | 1 周 | Tier A 开告警；Tier B 进队列；Tier C 仅留存 | 告警 precision 抽样 ≥ 90% |
| 3 统计（可选） | 2 周 | 部署方按需建设统计；本包只做规则内 Lua 阈值校准 | 规则/Lua 评分区分度达标 |
| 4 稳态 | 持续 | 周复核白名单/抑制/误报 | 误报工单 ≤ 5/天 |

### 9.2 调参方法

1. 用影子期数据计算每个特征的 P50/P90/P99（按业务域分组）。
2. 初始阈值取 P99 或"P99 + 业务确认"；不要用固定拍脑袋值。
3. 每周回算：新增白名单后，规则命中量应下降；若某规则命中量突然上升，先查数据源/解析器变更。
4. 任何阈值调整记录变更单，保留调整前后 7 天对比。

### 9.3 验收指标

| 指标 | 目标 | 计算方式 |
|---|---|---|
| 告警 precision | ≥ 95% | 每周抽样 50 条人工判定 |
| 误报工单 | ≤ 5 件/天 | 工单系统 |
| 合成用例召回 | ≥ 90% | `验证用例与上线清单.md` 中的正例集 |
| 合成用例误报 | 0 | `验证用例与上线清单.md` 中的反例集 |
| MTTD（隧道） | ≤ 15 min | 从首查询到事件 |
| 白名单命中率 | 监控项 | 白名单匹配/总查询 |
| 抑制审计覆盖率 | 100% | 每条 suppress 有 owner/到期 |

## 十、真阳性处置手册（摘要）

1. **确认**：查 `client_ip` 对应资产/用户；查 qtype、rcode、answers、TXT 长度；查 30 天历史是否首次出现。
2. **归因**：EDR 查发起进程/父进程/命令行；代理/TLS 查同域名 SNI；查是否命中已知隧道工具特征（iodine/dnscat2/dns2tcp/Cobalt Strike DNS beacon）。
3. **评估**：统计外泄字节（TXT rdata 总量）、持续时间、涉及主机数。
4. **处置**：隔离主机；解析器/防火墙封禁注册域（不是单个子域）；全量 DNS 日志回溯同域查询；抓包取证；按事件流程升级。
5. **复盘**：把该域加入 L1 IOC；检查白名单是否有过宽条目；更新规则/Lua 阈值。

## 十一、取舍与风险

| 取舍 | 影响 | 建议 |
|---|---|---|
| 白名单越宽，误报越低、召回越低 | 攻击者可利用被放行的 SaaS 域 | 只放行业务确认的注册域，90 天到期 |
| 统计阈值越严，误报越低、慢速隧道越易漏 | 慢速外泄 | 增加 30 分钟/24 小时长窗口与唯一子域比 |
| DoH 一律阻断 | 影响使用公共 DoH 的业务 | 先审计，再按业务放行批准端点 |
| 只做 IDS 不做解析器日志 | NAT 下无法归因 | 解析器日志是必选项 |
| 追求"绝对零误报" | 规则会退化到只报已知 IOC | 接受"告警队列零可执行误报"，用分级承接低置信线索 |
