# 命令与控制信标规则 · 质量、检出率、误报率与盲区分析

## 0. 结论

`10-命令与控制信标.rules` 共 6 条规则，核心问题是：

1. **全部使用 `alert http any any -> any any`**，没有方向。C2 信标本质是
   “内网主机 → 外部 C2”，应限定 `$HOME_NET/$CLIENT_NET -> $EXTERNAL_NET`；
2. **9110001/9110002 是单样本过拟合**：`/?a=&f=&t=&p=数字` 和固定 UA 只覆盖一个样本；
3. **9110003 的“Win7 + Firefox 48”UA 不是 C2 特征**，正常旧浏览器也会命中；
4. **9110004 的“缺失 Accept”误报高**，API 客户端、旧浏览器、精简客户端都可能缺失；
5. **9110005 的 `/api/client|file|task/...` 是通用管理 API 路径**，正常后台大量存在；
6. **9110006 的全单字母参数是分析/埋点/追踪接口常见结构**，误报高；
7. 没有 Body、Cookie、响应侧、TLS/JA3/SNI、IOC、周期/抖动分析；
8. 没有测试/CI；文件头“零误报”是**不成立的过度承诺**。

当前场景**没有已验证的 CI**；以下检出率/误报率均为机制分析，不是实测百分比。

---

## 1. 规则逐条审计

### 1.1 9110001 · 极简 GET 信标 + 固定 UA

```text
GET /?a=&f=&t=&p=123
UA: Mozilla/5.0 (Windows NT 6.1; rv:48.0) Gecko/20100101 Firefox/48.0
```

问题：

- 只覆盖一个样本的精确结构；
- **规范变更即漏报**：参数顺序、空值、额外参数、`p` 非数字、URL 编码、
  路径不是 `/`、大小写、POST 变体都不命中；
- UA 是精确 `content`（`|3b|` 即 `;`），任何空格/版本/顺序变化都漏报；
- 旧 Firefox UA 可能在正常旧系统/测试环境出现；
- `any any` 没有方向；
- “零误报”不成立：只要某个正常业务使用相同 URI 结构/UA 就会命中。

### 1.2 9110002 · 相同 URI 结构，UA 无关

- 比 9110001 稍宽，但仍然是一个固定样本结构；
- `^/\?` 要求路径正好是 `/`，`/index.php?...`、`/gate?...` 漏报；
- 参数值/顺序/数量固定；
- 正常埋点/分析接口可能使用 `a/f/t/p` 四个参数；
- `any any`；
- Medium/High 对结构匹配偏乐观。

### 1.3 9110003 · 陈旧矛盾浏览器 UA

```text
Windows NT 6.1.*rv:48.0
```

- 这是**旧浏览器特征**，不是 C2 特征；
- 正常旧 Win7/Firefox 48 客户端、虚拟机、测试环境会命中；
- C2 可以随意设置 UA，绕过；
- 没有 URI/Header/响应/资产上下文；
- Low/Medium 但 `classtype:trojan-activity`（优先级 1），分级矛盾。

### 1.4 9110004 · 缺失 Accept 头

- GET + HTTP/1.1 + UA 含 Mozilla + header_names 不含 Accept；
- API 客户端、精简客户端、旧浏览器、代理都可能缺 Accept；
- `content:!"Accept"` 对 `Accept-Encoding` 等相似头也可能产生语义歧义；
- 没有其他异常头组合，单信号误报高；
- `trojan-activity` + Low/Low 分级矛盾；
- 文件头也承认“误报偏高”。

### 1.5 9110005 · 控制面板 API 路径

```text
/api/(client|tunnel|file|dashboard|task|payload|beacon|session)/
    (list|ls|info|add|del|exec|upload|download)
```

- 这些是**通用后台/文件管理 API 词汇**；
- 正常网盘、运维平台、任务系统、会话管理、上传下载接口都可能命中；
- `/api/file/upload`、`/api/session/list`、`/api/task/info` 非常常见；
- 没有 C2 特有组合（例如同时出现 beacon/panel/agent + task/payload/session）；
- 没有资产/授权/响应上下文；
- Medium/Critical 过强。

### 1.6 9110006 · 全单字母参数

```text
/?a=1&b=2&c=3
```

- 埋点、分析、追踪、短链、广告参数大量使用单字母；
- 只要求 3 个以上单字母参数，没有值/路径/UA/响应上下文；
- 根路径限定会漏掉 `/collect?...` 等；
- Medium/High 过强。

## 2. 检出率与误报率

### 2.1 为什么不能给百分比

没有：

- 带标签的 C2 信标流量集；
- 与本案 SID 对齐的正反例；
- Cobalt Strike/Sliver/Mythic/Havoc/Brute Ratel 等版本的 HTTP profile 样本；
- 生产 shadow 结果。

因此不能声称“检出率 X% / 误报率 Y%”。文件头“零误报”没有依据。

### 2.2 机制判断

| 规则 | 检出能力 | 误报风险 |
|---|---|---|
| 9110001 | 只覆盖单个样本的精确 URI+UA；变种漏报 | 低到中，但“零”不成立 |
| 9110002 | 覆盖同一 URI 结构；路径/参数变体漏报 | 中：正常埋点可能同构 |
| 9110003 | 仅旧浏览器 UA；无 C2 特异性 | 高 |
| 9110004 | 仅缺失 Accept；无 C2 特异性 | 高 |
| 9110005 | 通用管理 API 路径 | 高 |
| 9110006 | 全单字母参数；无 C2 特异性 | 高 |

**综合**：只有 9110001/9110002 有样本价值，但都是过拟合；9110003-9110006
主要是低精度线索，不应以 `trojan-activity` 高优先级直接告警。

## 3. 盲区

### 3.1 方向/位置盲区

- 没有 `$HOME_NET -> $EXTERNAL_NET` 方向，入站/内部流量都可能误报；
- 只看 URI/UA/header_names，不看 Body、Cookie、响应；
- 不支持 POST/JSON/加密 payload；
- 不检查 Host/SNI 不一致、域名前置、CDN。

### 3.2 协议盲区

- HTTPS 未解密：看不到 URI/UA/Header；
- HTTP/2/HTTP/3：Lua HTTP1 API 不覆盖；
- DoH/DoT/DNS C2；
- 非 HTTP C2（TCP/UDP/WebSocket/gRPC）；
- JA3/JA4/SNI/证书异常未使用；
- 证书/域名 IOC 未使用。

### 3.3 行为盲区

- 没有信标周期/抖动/低慢速分析；
- 没有跨流聚合（规则内也不应做全局计数）；
- 没有请求/响应关联；
- 没有同一源对同一 URI 的重复访问模式；
- 没有 C2 框架 profile 识别（Cobalt Strike malleable、Sliver、Mythic、Havoc 等）；
- 没有任务下发/回传响应特征。

### 3.4 上下文盲区

- 正常埋点/分析/管理 API/旧浏览器/API 客户端；
- 授权红队/扫描器；
- NAT/代理/CDN 改变方向；
- 没有资产标签/IOC 数据集/业务白名单。

## 4. Lua/规则强化方向

### 4.1 方向修正

- 信标类：`$HOME_NET -> $EXTERNAL_NET` 或 `$CLIENT_NET -> $EXTERNAL_NET`；
- C2 面板 API：同样按外联方向；
- 响应侧：`$EXTERNAL_NET -> $HOME_NET`，用 `flowbits` 关联请求。

### 4.2 `c2_beacon.lua` 评分

不要单信号告警，改为多信号评分：

- URI 查询结构（a/f/t/p 或单字母参数）；
- 参数值长度/熵/空值比例；
- Header 异常组合：缺 Accept、缺 Accept-Language、缺 Referer、
  缺 Sec-Fetch-*、`Connection: close`；
- UA 与 Header 矛盾：旧 UA + 现代 TLS/HTTP2；
- 请求方法/路径异常；
- Host/SNI 不一致（需要 TLS 侧数据，HTTP Lua 不可见）；
- 响应侧确认（需 flowbits）。

建议阈值：至少 2-3 个独立信号才升级；单信号只做 telemetry。

### 4.3 C2 面板 API

不要用 `/api/file/upload` 这类通用路径单独告警。要求：

- 多个 C2 语义 token 组合：
  `beacon/agent/panel/client/tunnel` + `task/payload/session/command`；
- 非 GET 方法/认证/响应结构；
- 外部目标 + 资产标签；
- 否则 tier triage。

### 4.4 IOC 与指纹

- `http.host` + C2 域名/IP dataset（Suricata 8 string dataset 需 base64）；
- TLS SNI/JA3/JA4 规则（独立 TLS 场景，需 `requires: feature ja3`）；
- 证书异常/自签名/短有效期；
- C2 框架默认 profile/UA（需版本化样本，不能凭猜测写）；
- DNS/DoH/DoT 检测放在 DNS 场景。

### 4.5 响应侧

- 请求规则 `flowbits:set,c2_checkin`；
- 响应规则检查 C2 任务/回传特征：
  `task`、`payload`、`command`、`job`、`beacon`、`session` 等组合；
- 只作为 triage/alert，不作为“已确认 C2”。

### 4.6 建议调整

| SID | 建议 |
|---|---|
| 9110001 | 保留样本规则，改方向，`tier alert` 但去掉“零误报” |
| 9110002 | 改为 triage；要求额外 Header/响应信号 |
| 9110003 | 删除或降为 telemetry；旧 UA 不是 C2 |
| 9110004 | 删除或要求多 Header 异常 + 信标 URI |
| 9110005 | 改为 C2 token 组合 + 外联方向，tier triage |
| 9110006 | 改为 triage；要求额外信号，不能单凭单字母参数 |
| 新增 | IOC 域名/IP dataset、响应侧确认、JA3/SNI（独立场景） |

## 5. 验证建议

至少需要：

- 正例：
  - 9110001 精确样本；
  - 同结构变体（参数顺序/路径/编码）；
  - C2 面板 API 组合；
  - 单字母参数 + Header 异常；
- 反例：
  - 正常埋点 `?a=1&b=2&c=3`；
  - 正常 `/api/file/upload`、`/api/session/list`；
  - 旧 Firefox UA；
  - 正常 API 缺 Accept；
  - 正常 Host/URI；
- CI 精确断言 `signature_id`；
- `suricata -T`；
- 上传 EVE/日志 artifact。

---

## 6. 结论

`10-命令与控制信标.rules` 目前是“样本线索 + 通用管理 API 关键词”的混合：

- 9110001/9110002 有样本价值，但过拟合；
- 9110003/9110004/9110006 主要是低精度 Header/UA/参数线索；
- 9110005 很容易命中正常管理后台；
- 方向、Body、响应、TLS、IOC、周期分析均缺失；
- “零误报”不成立。

优先级建议：

1. 先修正方向（出站）；
2. 把 9110003/9110004/9110006 降为 telemetry 或删除；
3. 9110005 改为多 token 组合 + triage；
4. 增加 IOC dataset / 响应侧 / TLS 旁路（独立场景）；
5. 不要用单信号宣称“零误报”。

当前场景未修改规则，也未新增 CI；以上为分析与建议，落地前不能声称“已验证”。
