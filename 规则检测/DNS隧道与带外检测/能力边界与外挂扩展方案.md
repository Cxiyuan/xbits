# 规则内外挂：Lua 扩展与残余能力边界

> 问题：Suricata 8.0.8 能否在规则文件里直接引用脚本，把"外挂分析"变成规则的一部分？
> 结论：**能，但只能用 Lua。** Suricata 8.0.8 不支持 Python 规则脚本；检测侧的内嵌脚本是 `lua` 关键字与 `luaxform` 变换。本包已把能力扩展落到三条规则内嵌 Lua 规则（SID 9109201/9109202/9109203）及多条规则内 Lua 过滤，**不提供规则外工具或日志分析脚本**。

---

## 一、规则内嵌脚本的事实（Suricata 8.0.8）

| 项目 | 结论 |
|---|---|
| 规则内嵌脚本 | 支持 **Lua**：`lua:[!]<scriptfilename>;` |
| 缓冲区变换脚本 | 支持 **Lua**：`luaxform` 变换 |
| Python | **不支持**规则内嵌 Python；Python 只用于 `suricata-update`、`suricatasc` 等管理工具 |
| Lua 版本 | 8.0 起使用 Lua 5.4，规则内 Lua 默认启用 |
| 沙箱 | 默认沙箱：只有 base/table/string/math/utf8；**没有 io/os/package/debug** |
| 预算 | 每次调用有指令数/内存上限（默认约 50 万条指令、500KB，可配置） |
| DNS API | `require("suricata.dns")`；`dns.get_tx()` 后调用 `queries()`、`answers()`、`rcode()`、`rcode_string()`、`rrname()` |
| 规则 hook | `alert dns:request_complete ...` / `alert dns:response_complete ...` |
| 脚本路径 | `lua:` 的文件名会追加到 `default-rule-path`（通常是 `/etc/suricata/rules/`） |
| 关键实现细节 | Lua 规则**必须带一个 buffer**（请求用 `dns.query`，响应用 `dns.queries.rrname`）；只有 hook 没有 buffer 的规则会被当作 straight match，脚本不会执行 |

**Python 不能内嵌**这一点很关键：如果坚持用 Python 逻辑，只能把它放在 SIEM/离线管道里，无法"由规则直接调用"。规则内能做到的扩展，必须用 Lua 重写。

---

## 二、Lua 在规则内能做什么、不能做什么

| 能力 | Lua 规则内 | 说明 |
|---|---|---|
| 单事务 qname 熵/字符集/标签长度/深度 | ✅ | 本包 9109201 及 9109001/2/3/6 的 Lua 过滤 |
| 单事务 qtype、rcode、answer 数、TTL | ✅ | `queries()`/`answers()`/`rcode_string()` |
| 响应侧 TXT/NULL 载荷长度/内容 | ✅ | `answers()[i]["addr"]`，本包 9109202/9109203 |
| 读取 `dns_tunnel_allow.lst` | ❌ | 沙箱无 io；白名单仍由规则里的 `dataset` 完成 |
| 跨包/跨事务聚合（唯一子域数、比例、长窗口） | ❌（不可靠） | 状态是 per-thread 的，且受内存/指令预算限制 |
| 资产/进程/用户上下文 | ❌ | 需要 EDR/CMDB |
| DoH/DoT 解密 | ❌ | 需要代理/端点遥测 |
| 修改/标准化 buffer | ✅（`luaxform`） | 适合自定义归一化，不是本包主路径 |

> 结论：**Lua 把"单事务能判断的特征"全部收进规则，显著提升编码/结构类检出并降低误报；但"跨事务聚合/资产上下文"仍是规则外的事。**

## 三、本包的 Lua 规则

### 3.1 SID 9109201 · 请求侧编码/结构评分

```text
alert dns:request_complete $CLIENT_NET any -> any 53 ( \
    msg:"[DNS隧道-Lua] 请求侧编码/结构评分"; \
    flow:to_server; \
    dns.query; to_lowercase; dotprefix; \
    dns.rrtype:!12; \
    dataset:isnotset,dns_tunnel_allow, type string, match subdomain, load dns_tunnel_allow.lst; \
    lua:dns_tunnel_request.lua; \
    flowbits:set,dns_susp; \
    classtype:non-standard-protocol; \
    metadata:..., tier triage, engine lua; \
    sid:9109201; rev:1;)
```

Lua 评分项（`lua/dns_tunnel_request.lua`）：

- 最左标签与全标签的最大香农熵、最长标签、深度
- hex/base32/base64url 字符集占比
- qtype 分级：A/AAAA 要求更强证据；TXT/NULL/CNAME 保持敏感
- RFC 4122 UUID 版本/变体校验
- 任意位置的服务标签、punycode、高连字符标签跳过
- 静态高频域安全网 + 规则内 `dataset` 主白名单

同一脚本也作为 9109002（32hex）、9109003（UUID）、9109006（长标签）的二次过滤。

### 3.2 SID 9109202 · 响应侧 TXT/NULL 载荷

```text
alert dns:response_complete any 53 -> $CLIENT_NET any ( \
    msg:"[DNS隧道-Lua] 响应侧 TXT/NULL 大载荷"; \
    flow:to_client; \
    dns.queries.rrname; \
    lua:dns_tunnel_response.lua; \
    classtype:trojan-activity; \
    metadata:..., tier triage, engine lua; \
    sid:9109202; rev:1;)
```

Lua 评分项（`lua/dns_tunnel_response.lua`）：

- TXT/NULL `addr` 字节量、answer 数、最小 TTL
- **载荷内容分类**：SPF/DKIM/DMARC/域名验证前缀、人类可读文本不计入大载荷
- **CNAME target** 的熵/长度分析（补 CNAME 隧道）
- 任意位置的服务标签、punycode、高连字符标签跳过
- qname 无结构特征时不因 TXT 大而告警

### 3.3 SID 9109203 · 请求 + 响应联合确认

```text
alert dns:response_complete any 53 -> $CLIENT_NET any ( \
    msg:"[DNS隧道-Lua] 请求+响应确认的隧道"; \
    flow:to_client; \
    dns.queries.rrname; \
    flowbits:isset,dns_susp; \
    lua:dns_tunnel_confirm.lua; \
    classtype:trojan-activity; \
    metadata:..., tier alert, engine lua; \
    sid:9109203; rev:1;)
```

- 请求侧规则命中后设置 `flowbits:dns_susp`
- 响应侧只有出现编码载荷 / 异常 CNAME 时才升级为高置信
- A/AAAA 正常响应不会升级，降低 CDN/缓存 token 与 DGA 误报
- 若 DNS query/response 不在同一 flow，9109203 可能不触发；9109202 仍提供独立线索

### 3.4 其余规则内的 Lua 二次过滤

| 脚本 | 规则 | 作用 |
|---|---|---|
| `dns_compact_labels.lua` | 9109001 | 只放行连续十六进制单字符流 |
| `dns_oob_request.lua` | 9109004/5 | 拒绝平台根域/短 token；限定 qtype |
| `dns_txt_burst.lua` | 9109103 | 跳过邮件认证/服务发现与 apex TXT |
| `dns_dot_policy.lua` | 9109101 | ALPN `dot` + SNI 二次过滤 |
| `dns_doh_policy.lua` | 9109102 | HTTP method/URI/host 二次过滤 |

## 四、规则内能力的边界

本包只交付**规则 + 规则内 Lua + dataset**，不提供规则外脚本、日志读取器或离线分析工具。
Lua 解决"单事务"问题，以下问题属于引擎边界，不在本包范围内：

| 残余问题 | 本包是否覆盖 | 原因 |
|---|---|---|
| 慢速/低频隧道（每分钟 1 条） | 否 | Lua 无跨包状态，per-thread 计数不可靠 |
| 唯一子域数/比例、NXDOMAIN 比、qtype 混合 | 否 | 需要跨事务窗口，规则层不实现 |
| 客户端归因（NAT/出口） | 否 | 规则只看包，拿不到真实客户端 |
| 进程/资产/用户 | 否 | 规则层没有这些字段 |
| DoH/DoT/DoQ | 否 | 加密 DNS 不可见 |
| 域名年龄/信誉 | 否 | 需要外部数据源 |
| 白名单维护 | 部分 | 规则只负责加载 `.lst`；条目由人工维护 |

> 如果部署方需要上述能力，应在规则/引擎之外自行建设；本包不包含对应脚本或工具。
> 规则内仍可继续用 Lua 降低误报的场景，见 `Lua强化检测场景.md`。

## 五、部署

1. 把 `lua/*.lua` 复制到 **default-rule-path**（通常 `/etc/suricata/rules/`），与 `DNS隧道与带外检测规则.rules`、`dns_tunnel_allow.lst` 同目录。
2. 确认 Lua 规则启用（8.0 默认启用；若被关闭，在 `suricata.yaml` 打开 `security.lua.allow-rules`）。
3. 校验：

   ```bash
   suricata --version        # 必须 8.0.8
   suricata -T -c /etc/suricata/suricata.yaml \
             -S /etc/suricata/rules/DNS隧道与带外检测规则.rules -v
   ```

4. 用小流量 PCAP/`dig` 验证三条 Lua 规则与二次过滤命中（见 `验证用例与上线清单.md` 的用例）。
5. 观察 `stats.log`：`lua_rule_errors`、指令/内存限制错误；确认没有脚本异常。

### 性能注意

- 主要 Lua 规则会在每个 DNS 事务上各调用一次；脚本只做标签/answer 的小循环，通常可接受。
- 若 QPS 很高，先测 CPU；可只启用 9109202（响应侧）或把请求侧阈值调高。
- 不要用 Lua 维护跨请求的大表：per-thread 状态 + 内存上限会带来不可控行为。

## 七、一句话回答

**Suricata 8.0.8 的规则内嵌脚本是 Lua，不是 Python。** 本包用三条 Lua 规则把"请求侧熵/字符集/结构评分"和"响应侧 TXT/NULL 载荷"收进规则，直接提升编码/响应侧检出并降低误报；**跨事务聚合、慢速行为、资产/进程上下文、加密 DoH/DoT 内容仍需规则外组件**；DoT/DoH 的 ALPN/SNI/HTTP 元数据已由规则内 Lua 过滤。这是引擎边界，不是脚本写法问题。
