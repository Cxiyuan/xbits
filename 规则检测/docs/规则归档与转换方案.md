## 2. 归档原则

| 内容 | 归档 |
|---|---|
| Snort 风格 `.rules`、Lua、`.lst` | `suricata/<攻击类别>/` |
| Zeek 场景评分脚本 `.zeek` | `zeek/<场景>/` |
| SID 元数据、成功确认依赖、例外表 | `xbits/规则库元数据/` |
| 邮件 `mail_uri` 规则 | 不进 Suricata，仅元数据（待 SMTP 专项） |
| 云审计 `action:log audit` | 仅 xbits 元数据 |
| 厂商二进制规则库（编译格式） | 不转换（无明文语义） |
| `lib_*` 基线规则 | 不转换（与现网 `etc_fw` SID 重复） |

## 3. 转换规则（convert_probe_rules.py）

输入：`桌面/流量检测规则`（加密规则库解密后的明文导出）。

1. `uricontent:"X"` → `content:"X"; http_uri;`（等价）
2. `<>` 双向操作符 → `->`；仅保留带 `flow:` 方向约束的规则，无 flow 的剔除
3. 元数据从 Suricata 规则剥离，但保留在 `rules_meta.json` / `sid_library.json`：
   `ruletype` / `holetype-id` / `scope_id` / `depend` / `depended` /
   `classtype` / `reference`
4. `status_code:N` 不再剥离：转换为 `content:"N"; http_stat_code;`；多值/非数字剔除
5. 无法等价转换的语义一律剔除，不降级使用：
   `http_only_uri` / `rate` / `rawbytes` / `resp` / `logto` / `method` /
   悬空 `http_uri` / 响应方向请求侧缓冲 / 绝对与相对定位混用 / 重复定位
6. `pcre` 不兼容规则（负向、`R/P/B`、PCRE2 编译不通过）跳过
7. PVS `depend/scope` 语义 → Suricata flowbits 门控：
   - 被依赖的请求侧 SID 追加 `flowbits:set,xb_dep_<sid>`
   - 带依赖的响应侧规则追加 `flowbits:isset,xb_dep_<主依赖>`
   - 无依赖或依赖链不完整的成功确认规则不进 Suricata
8. 按 SID 去重；清理后删除 orphan flowbits、空规则文件和空目录
9. 规则按 `CATEGORY_MAP` 落入攻击类别目录；弱/泛化规则标记 `tier=weak`

所有被剔除规则的 SID 与原因写入 `xbits/规则库元数据/semantic_gaps.json`、
`dead_rules.json`，只保留元数据，不进入 Suricata。

## 4. 转换产物（最近一次运行）

- Suricata active 规则：18,812 条（47 个文件），按类别分布到 `suricata/<类目>/`
- 攻击成功确认：526 条依赖关系，flowbits 门控
- 云审计：189 条（仅元数据）
- SID 映射：31,712 条（名称/类别/危险等级/reference/classtype 等）
- 语义降级/不可等价转换隔离：12,446 条（仅元数据）
- 例外/强 SID：`xbits/规则库元数据/exceptions.json`

## 5. 联动语义

Suricata 命中 `flowbits:set` 请求侧规则 → EVE alert（带 sid）→ xbits；
同一流量响应侧命中 `flowbits:isset` 成功确认规则 → EVE alert → xbits；
xbits 依据 `success_rules.json` 按 5-tuple 关联，确认“攻击成功”后输出高置信度告警。

弱规则（tier=weak）命中默认低置信度，需 Zeek 上下文或成功确认后才输出。

## 6. 已知限制

- 厂商二进制规则库（request/response）未转换。
- 邮件 `mail_uri` 规则未进 Suricata，留待 SMTP 专项。
