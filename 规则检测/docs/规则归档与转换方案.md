## 2. 归档原则

| 内容 | 归档 |
|---|---|
| Snort 风格 `.rules`、Lua、`.lst` | `suricata/<攻击类别>/` |
| Zeek 场景评分脚本 `.zeek` | `zeek/<场景>/` |
| SID 元数据、成功确认依赖、例外表 | `xbits/规则库元数据/` |
| 邮件 `mail_uri` 规则 | 不进 Suricata，仅元数据（待 SMTP 专项） |
| 云审计 `action:log audit` | 仅 xbits 元数据 |
| 厂商二进制规则库（编译格式） | 不转换（无明文语义） |
| `lib_*` 基线规则 | 不转换（与现网 `etc_fw` SID 重复） |

## 3. 转换规则（convert_probe_rules.py）

输入：`桌面/流量检测规则`（加密规则库解密后的明文导出）。

转换核心是**语义树归约**（V-10 重写，不再是逐 token 重写）：
解析器先把规则选项归约成 `(buffer, content/pcre, 修饰词)` 原子序列——
Snort 语义「`content` 在前、其后紧跟的 buffer 修饰词只修饰该 content」
（含 `uricontent:"X"` 语法糖与 pcre 的 `U/I/H/D/C/P/Q/M/V/W/Z/S/Y` buffer 标志）
统一归约到语义树；再按 Suricata 语义「sticky buffer 只作用于其后的匹配」
线性化为 `buffer; content:"X"; 修饰词;`。跨 buffer 段用 `pkt_data` 显式
回到 payload，避免把后续匹配误绑到前一个 buffer。

1. `uricontent:"X"` → 语义树绑定 `http.uri`，输出 `http.uri; content:"X";`
   （**不是等价的 token 重写**：旧写法 `content:"X"; http_uri;` 在 Suricata 里
   buffer 只约束其后的匹配，`content:"X"` 会落回 payload——语义反转。
   输出统一使用 Suricata 8 点分 sticky buffer 名：下划线旧名（`http_uri` 等）
   是 content 修饰词，只能跟在 content 之后，前置会被解析器拒绝）
2. `<>` 双向操作符 → `->`；仅保留带 `flow:` 方向约束的规则，无 flow 的剔除
3. **按 flow 方向决定规则头端口/网段位置**（V-16/V-18）：`flow:to_server`
   （及缺省）保持服务端口在目的侧（`any any -> any $HTTP_PORTS`）；
   `flow:to_client` / `flow:from_server` 若目的端口是**服务端口表达**（端口组
   变量 `$HTTP_PORTS`、数字端口 `443`、列表 `3306,1521,1433,5432`、
   范围 `[139,445]`、`5900:6000`、开口范围 `1024:`、混合 `21,22,$HTTP_PORTS`），
   交换「网段+端口」对，输出 `any <服务端口> -> any any`（响应报文源端口才是
   服务端口，目的端口是客户端临时端口）。已是正确的 `any <服务端口> -> any any`
   不重复翻转；`any` 与明确客户端端口（DHCP 68）允许留在目的侧。静态断言：
   to_client 且目的端口仍残留**任何服务端口表达**→拒绝生成并计数
   （`to-client-port-direction`），计数写入 `conversion_report.json`；
4. 元数据从 Suricata 规则剥离，但保留在 `rules_meta.json` / `sid_library.json`：
   `ruletype` / `holetype-id` / `scope_id` / `depend` / `depended` /
   `classtype` / `reference`
5. `status_code:N` 转换为独立状态码段 `http_stat_code; content:"N";`；
   段内仅允许该状态码 content，其后的匹配必须显式重置 buffer（`pkt_data` /
   新 sticky buffer）；生成器静态断言 buffer 容量上界（`http_stat_code`=3、
   `http_method`≤16）——绑定到容量型 buffer 的 content 超长即拒绝生成
   （该匹配在数学上不可能命中）；多值/非数字剔除
6. 无法等价转换的语义一律剔除，不降级使用：
   `http_only_uri` / `rate` / `rawbytes` / `resp` / `logto` / `method` /
   无承接匹配的悬空 sticky buffer（`buffer-without-payload`）/
   响应方向请求侧缓冲 / 绝对与相对定位混用 / 重复定位
7. `pcre` 不兼容规则（负向、`R/P/B` 修饰标志）跳过；
   buffer 标志按语义树绑定（树已绑定时剥离冗余标志）
8. 转换规则的 PVS `depend/scope` 语义不再注入 Suricata flowbits：
   - 请求→响应成功确认规则只保留元数据，写入 `success_rules.json`；
   - 转换规则的 `noalert`、`flowbits:set/isset` 不进入 active 规则；
   - 自研场景保留 19 条 flowbits、41 条 Lua、63 条 threshold，用于签名增强；
9. 按 SID 去重；清理后删除空规则文件和空目录
10. 规则按 `CATEGORY_MAP` 落入攻击类别目录；弱/泛化规则标记 `tier=weak`

所有被剔除规则的 SID 与原因写入 `xbits/规则库元数据/semantic_gaps.json`，
只保留元数据，不进入 Suricata。to_client 方向翻转与静态断言计数写入
`xbits/规则库元数据/conversion_report.json`。

## 4. 转换产物（最近一次运行）

- Suricata active 规则：19,447 条（转换 19,373 + 场景 74；buffer 输出统一为
  Suricata 点分 sticky buffer 名，见语义树说明）
- 自研场景保留 33 个 Lua 脚本、41 条 `lua:` 规则；Web Lua 签名增强保留
- 请求→响应成功确认依赖元数据：996 条，供 xbits 后续关联
- 云审计：189 条（仅元数据）
- SID 映射：31,712 条（名称/类别/危险等级/reference/classtype 等）
- 语义/行为/关联隔离：12,150 条（仅元数据；`dangling-http-uri` 2,073 条
  系旧版误判已回流；`byte-extract-reference` 13 条为 byte_extract 变量引用，
  静态无法校验；见语义树说明）
- 例外/强 SID：`xbits/规则库元数据/exceptions.json`

## 5. 联动语义

- Suricata：只输出 content/pcre/byte_* 签名命中；
- Zeek：只输出 DNS 突发、侦察频率、C2 重复 URI 等行为日志；
- xbits：按 `community_id`/5-tuple 消费两类事件，做去重、置信度和关联；
  `success_rules.json` 提供请求→响应依赖，供后续深度关联实现。

弱规则（tier=weak）命中默认低置信度，需 Zeek 行为上下文或成功确认后才输出。

## 6. 已知限制

- 厂商二进制规则库（request/response）未转换。
- 邮件 `mail_uri` 规则未进 Suricata，留待 SMTP 专项。
- 语义树转换不改变源规则的编写错误（如 `content:"POST"; http_uri;` 指望
  POST 出现在 URI）：源规则语义原样保留，错误作者意图需要规则源修正。
