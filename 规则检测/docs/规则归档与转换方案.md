# 规则检测目录归档与 Sangfor 规则转换方案

## 1. 目录结构（按消费源归档）

```
规则检测/
├─ suricata/                       # Suricata 消费的规则 + Lua + 数据集
│  ├─ DNS隧道与带外检测/            # 自研场景规则
│  ├─ Web漏洞利用/
│  ├─ 侦察与攻击工具指纹/
│  ├─ 后门通信/
│  └─ sangfor/                     # 深信服探针导出的转换规则
│     ├─ *.rules                   # 强规则（IPS/WAF/PVS/UTM）
│     ├─ weak/                     # 弱/泛化规则（低置信度，交 xbits 收敛）
│     └─ success/                  # PVS 成功确认规则（flowbits 门控）
├─ zeek/                           # Zeek 消费的场景脚本
│  ├─ DNS隧道与带外检测/dns_tunnel_score.zeek
│  ├─ Web漏洞利用/web_exploit_chain.zeek
│  ├─ 侦察与攻击工具指纹/recon_score.zeek
│  └─ 后门通信/backdoor_c2_score.zeek
├─ xbits/                          # xbits 中央分析引擎消费的数据
│  ├─ sangfor/
│  │  ├─ rules_meta.json           # 每条规则元数据（depend/scope/holetype/tier）
│  │  ├─ success_rules.json        # PVS 成功确认依赖（攻击成功判定）
│  │  ├─ audit_rules.json          # 云审计规则（仅元数据）
│  │  ├─ sid_library.json          # SID → 名称/类别/危险等级映射
│  │  └─ exceptions.json           # 例外/强 SID 列表
│  └─ analysis.json → ../xbits/rules/analysis.json（中央引擎规则仍在 xbits/rules/）
├─ docs/                           # 规则设计/误报分析文档
└─ convert_sangfor.py              # Sangfor 导出 → 项目规则转换器
```

注意：`docker/sangfor-validate.yaml` 由转换器生成（Suricata 加载验证配置），
`测试用例/classification.config`、`reference.config` 仍是 Suricata 配套文件。

## 2. 归档原则

| 内容 | 归档 | 理由 |
|---|---|---|
| Snort 风格 `.rules`、Lua、`.lst` 数据集 | `suricata/` | Suricata 加载 |
| Zeek 场景评分脚本 `.zeek` | `zeek/` | Zeek 加载 |
| PVS depend/scope 依赖、SID 映射、例外表 | `xbits/` | 中央引擎联动/误报消除 |
| 邮件 mail_uri 规则 | 不进 Suricata | Suricata 无 mail_uri 语义，需 SMTP 侧解析（后续专项） |
| 云审计 `action:log audit` | 仅 xbits 元数据 | 审计事件不是高置信度告警 |
| `sangfor_waf_rules/request.rules`（二进制） | 不转换 | 深信服私有编译格式，无明文语义 |
| lib_ips_feature / lib_waf / lib_utm 基线库 | 不转换 | 与 etc_fw 现网规则 SID 重复 |

## 3. 转换规则（convert_sangfor.py）

输入：`桌面/流量检测规则`（深信服 TS3.0.99 FRC4 解密后的明文导出）。

转换处理：

1. `uricontent:"X"` → `content:"X"; http_uri;`
2. `<>` 双向操作符 → `->`（Suricata 不支持 `<>`）
3. 剥离 Sangfor 私有关键字（保留到 `rules_meta.json`）：
   `ruletype` / `holetype-id` / `scope_id` / `depend` / `depended` / `action:log audit`
4. 剥离全部 `classtype`（未知 classtype 会导致 Suricata 拒绝加载；类别语义在
   `xbits/sangfor/sid_library.json`，由 hole_library.ini + classification.json 还原）
5. 剥离 Snort-only 关键字：`resp` / `logto`
6. PVS `depend/scope` 语义 → Suricata flowbits 门控：
   - 被依赖的请求侧规则（741 个 SID）追加 `flowbits:set,xb_dep_<sid>;`
   - 带依赖的成功确认规则（996 条）追加 `flowbits:isset,xb_dep_<主依赖>;`
   - 无任何依赖的“成功确认”规则（6086 条，多为 200 OK 泛匹配）不进 Suricata，
     避免大量噪声；其元数据仍保留在 rules_meta.json 供 xbits 使用
7. 按 SID 全局去重（现网 etc_fw 内部重复 120 条）
8. 弱/泛化规则分档到 `weak/`（gray_keyword、sql.weak、information_disclose、
   web_scan、malice_url_report），标记 `tier=weak`，由 xbits 低置信度收敛

## 4. 转换产物统计（最近一次运行）

- Suricata 强规则：约 25.9k 条（39 个文件）
- Suricata success 规则（flowbits 门控）：996 条（4 个文件）
- Suricata weak 规则：5 个文件
- xbits success_rules.json：996 条依赖关系
- xbits sid_library.json：31,712 个 SID 映射（名称/类别/危险等级）
- xbits audit_rules.json：189 条云审计
- 例外表：ips/waf exception（当前为空）+ ips_strongsid（192 个强 SID）

## 5. 联动语义

Suricata 命中 `flowbits:set` 请求侧规则 → EVE alert（带 sid）→ xbits；
同一流量响应侧命中 `flowbits:isset` success 规则 → EVE alert → xbits；
xbits 依据 `success_rules.json` 的 depends/scopes 将两者按 5-tuple 关联，
确认“攻击成功”后输出高置信度告警（confidence 提升 + evidence 标注 success sid）。

弱规则（tier=weak）命中默认低置信度，需 xbits 结合 Zeek 上下文
（http host/uri/status/ua）或 success 确认后才输出。

## 6. 已知限制

- `etc_fw/pvs/rules/webshell.rules` 与 `etc_fw/waf/rules/webshell.rules` 在 Windows
  主机上被 Defender 实时防护拦截读取（错误 22），本次转换跳过；两个文件需在
  Linux/关闭实时防护的环境重跑转换器补齐。webshell 检测仍由可读的
  `waf/webshell_rules/webshell_detect.rules`（2,544 条）覆盖大部分场景。
- `sangfor_waf_rules/request.rules` 等二进制规则库不含明文语义，未转换。
- 邮件 `mail_uri` 规则未进 Suricata，留待 SMTP 专项。
