## 2. 归档原则

| 内容 | 归档 |
|---|---|
| Snort 风格 `.rules`、Lua、`.lst` | `suricata/<攻击类别>/` |
| Zeek 场景评分脚本 `.zeek` | `zeek/<场景>/` |
| SID 元数据、成功确认依赖、例外表 | `xbits/规则库元数据/` |
| 邮件 `mail_uri` 规则 | 不进 Suricata，仅元数据（待 SMTP 专项） |
| 云审计 `action:log audit` | 仅 xbits 元数据 |
| 厂商二进制规则库（编译格式） | 不转换（无明文语义） |
| `lib_*` 基线规则 | 不转换（与现网 `etc_fw` SID 重复） |

## 3. 转换规则（convert_probe_rules.py）

输入：`桌面/流量检测规则`（加密规则库解密后的明文导出）。

1. `uricontent:"X"` → `content:"X"; http_uri;`
2. `<>` 双向操作符 → `->`
3. 剥离厂商私有关键字（保留到 `rules_meta.json`）：
   `ruletype` / `holetype-id` / `scope_id` / `depend` / `depended` /
   `action:log audit` / `status_code`
4. 剥离全部 `classtype`（未知 classtype 会导致 Suricata 拒载；类别语义走
   `sid_library.json`，由 `hole_library.ini` + `classification.json` 还原）
5. `http_only_uri`、pcre 后的重复 `nocase`、请求侧缓冲与响应方向的冲突组合：
   按选项级清理（丢弃或改写），无法等价表达的规则只保留元数据
6. 负向 pcre（`pcre:!"..."`）规则跳过（Suricata 不支持）
7. PVS `depend/scope` 语义 → Suricata flowbits 门控：
   - 被依赖的请求侧 SID 追加 `flowbits:set,xb_dep_<sid>`
   - 带依赖的响应侧规则追加 `flowbits:isset,xb_dep_<主依赖>`
   - 无依赖的“成功确认”规则（多为 200 OK 泛匹配）不进 Suricata
8. 按 SID 去重（现网 `etc_fw` 内部重复约 120 条）
9. 规则按 `CATEGORY_MAP` 落入攻击类别目录；弱/泛化规则（敏感关键词、弱 SQL、
   信息泄露、扫描器、恶意 URL）标记 `tier=weak`，仍归入对应类别，由 xbits 收敛

## 4. 转换产物（最近一次运行）

- Suricata 规则：约 23.5k 条，按类别分布到 `suricata/<类目>/`
- 攻击成功确认：989 条依赖关系，flowbits 门控
- 云审计：189 条（仅元数据）
- SID 映射：约 30.8k 条（名称/类别/危险等级）
- 例外/强 SID：`xbits/规则库元数据/exceptions.json`

## 5. 联动语义

Suricata 命中 `flowbits:set` 请求侧规则 → EVE alert（带 sid）→ xbits；
同一流量响应侧命中 `flowbits:isset` 成功确认规则 → EVE alert → xbits；
xbits 依据 `success_rules.json` 按 5-tuple 关联，确认“攻击成功”后输出高置信度告警。

弱规则（tier=weak）命中默认低置信度，需 Zeek 上下文或成功确认后才输出。

## 6. 已知限制

- `etc_fw/pvs/rules/webshell.rules` 与 `etc_fw/waf/rules/webshell.rules` 在 Windows
  主机上被 Defender 实时防护拦截读取，本次转换跳过；需在 Linux/关闭实时防护
  环境重跑转换器补齐。webshell 检测仍由可读的
  `webshell_rules/webshell_detect.rules`（2,544 条）覆盖大部分场景。
- 厂商二进制规则库（request/response）未转换。
- 邮件 `mail_uri` 规则未进 Suricata，留待 SMTP 专项。
