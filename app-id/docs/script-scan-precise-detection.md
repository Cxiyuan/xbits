# 精准识别"脚本化扫描"的方法（供 scan.zeek 实现）

> 目标：对**自研/脚本扫描器**（Python/Go/Rust/C 复用 HTTP/TLS 库）做到"高精度、近零误报"的识别。
> 前提：单个指纹（UA/JA3/头）都不够；**精准 = 多维度独立证据 + 行为为主 + 基线/白名单 + 影子评估**。

## 1. "精准"的两个层级（先分清）
- **A. 判定"脚本化扫描行为"（category=scanner，可高精度）**：靠行为+库指纹组合，不依赖具体工具。
- **B. 判定"具体工具"（app=nuclei/ffuf…）**：只有命中工具独有 UA/探针字面才可定到具体工具。
> 现实建议：A 做准（产品价值最大），B 能定则定。

## 2. 证据维度（按"抗伪造"排序，行为最硬）
| 维度 | 具体特征 | 抗伪造 |
|---|---|---|
| **行为（最硬）** | 请求速率、URI 广度/枚举、404/403 比例、端口发散、连接寿命、无静态资源、单请求连接、参数/ID 可预测 | 强（改指纹也难改行为） |
| 会话/头部 | 头部顺序/大小写、缺 `Accept-Language/sec-ch-ua/Cookie/Referer`、库默认头组合 | 中 |
| 传输指纹 | JA3/JA4、HTTP/2 SETTINGS/伪头顺序、ALPN | 中（可被 utls/curl-impersonate 伪装） |
| 上下文/图 | 同源多目标、同指纹跨多 dest、DNS/PTR 扫 | 强 |
| 应答关联 | 软 404、状态码分布、响应长度差异 | 强 |

## 3. 精准判定模型：两阶段 + 硬门槛 + 打分
### 阶段一：候选生成（Gate，任一即入候选）
- 库指纹命中（UA/JA3/JA4/H2 属"脚本客户端库"）；
- 非浏览器头集合（缺浏览器常规头，UA 为库默认）；
- 行为异常（下列任一超阈）。

### 阶段二：确认（Confirm，需"行为分 ≥ 阈值" **且** ≥2 个独立维度）
> 仅当候选同时满足行为门槛，才判 `scanner`；否则只记 `client_lib` 线索。

**行为硬指标（初始建议值，需按真实基线校准）：**
- 目录/路径爆破：同一 `orig_h` 在 60s 内对同一 `host` 请求 **≥50 个不同 URI**，且 **404+403 占比 ≥70%**。
- 参数/路径枚举：URI 含高熵/序号递增/字典词，且单位时间唯一 URI 增速高。
- 端口扫描：同源 60s 内 **≥20 个不同 dst 端口**，多为短命连接（SYN 后 RST/无应用数据）。
- 脚本客户端特征：UA 为空或库默认 + 缺浏览器头 + 高频。
- 一致性：同源对多目标、同 `JA3` 跨多 `dest`（扫描基础设施）。

**打分示例（可调）：**
```
score = 3*行为命中数 + 2*库指纹命中 + 1*头部异常 + 1*应答异常
scanner 判定：score>=5 且 行为命中>=1；输出 confidence（低/中/高）+ evidence 列表
```

## 4. 降低误报的工程手段（决定"精准"成败）
1. **按源聚合**（`orig_h`），窗口滑动的状态表；不要按单包/单请求判。
2. **硬门槛**：没有"行为"证据绝不判 scanner（避免把 requests/Go/curl 正常调用误判）。
3. **白名单/基线**：业务服务、监控/健康检查、CI、CDN 回源、压测机、NAT 出口（NAT 下**同 IP 多用户**易误报，需按会话/UA 细分）。
4. **滞后与冷却**：超阈后进入观察窗再确认，命中后冷却去重。
5. **影子模式**：先只记录不阻断，统计 FPR/误报样本再调阈值。
6. **证据落库**：每条判定附 evidence（命中的 URI 数、404 比、JA3、UA、端口数…），便于复核与调参。

## 5. 抗规避（现实边界）
- `curl-impersonate`、Go `utls`、JA3 伪装可伪造 TLS/H2 指纹；UA 更易改。
- **行为是最难伪装的**（要像扫描就必然高频/广撒网/枚举）；
- **Low-and-slow 扫描**（慢速、分散、低频）难被短窗规则发现 → 需长窗口/UEBA/ML 辅助，且精度下降。
- 结论：**无法 0 漏报**；但"行为+指纹双证"可做到**近零误报**。

## 6. ML/UEBA（可选增强，不作唯一依据）
- 特征：请求速率/熵、URI 广度和字典相似度、状态码分布、包长序列、连接时长、并发数、JA3/JA4、H2 指纹。
- 有监督需标注（扫描器正样本 + 正常负样本）；无监督做异常打分。
- 仅作加分/排序，不单独判 scanner；持续回流修正。

## 7. 评估方法（把"精准"变成可度量）
- 建**正样本**：多语言/多库扫描器（requests/aiohttp/httpx、Go net/http、Rust reqwest、libcurl、scapy、常见工具）。
- 建**负样本**：浏览器、API 客户端、监控探针、健康检查、CI、CDN、压测、NAT 多用户。
- 指标：Precision/Recall；**负样本 FPR 目标 ≈ 0**；阈值上线前必须过负样本回归。
- 定期回归（指纹/库版本变化、业务变更）。

## 8. 落地到 scan.zeek 的要点（实现提示）
- 状态：`global scan_state: table[addr] of ... &create_expire=...`（按源窗口聚合）。
- 事件：
  - `http_request` 累计唯一 URI、UA、缺头情况；`http_reply` 统计 404/403；
  - `conn` 统计 dst 端口数/短命连接；
  - `ssl` 取 JA3/JA3S（JA4 待 9.0.1 核验）；HTTP/2 指纹需分析器能力（待核验）。
- 打分与门控按 §3；达阈值调用 `XbitsAppId::note_app(...)` 并写 `scan_verdict`/`evidence`。
- 先影子模式上线，按证据人工抽检校准阈值。

## 9. 结论
- **精准识别"脚本化扫描行为"是可行的**：以**行为为主、指纹为辅**，两阶段 + 硬门槛 + 基线/白名单，可达高精度、近零误报。
- **精准识别"具体工具"**只有命中工具独有 UA/探针字面时才成立。
- **零漏报不可能**（伪装/慢速扫描）；工程目标应为"**真实流量下近零误报 + 可解释证据 + 可调阈值**"。
